- **Every mutating request to an audited path is recorded, including denied ones.** The matrix sent one `POST /api/staff` and one `POST /api/departments` per principal, and all 12 attempts appear with the caller's user id, email and role, and a UTC timestamp. Only Admin was authorised; the rest received 403 or 401. The Admin probes sent `{}`, so they were rejected by validation and nothing was created.
- **Gap:** an entry does not record the **outcome**. `AuditLogMiddleware` stores who, what and when, but not the HTTP status, so a Doctor's denied attempt reads the same as a successful Admin create. Adding `context.Response.StatusCode` to the entry is a one-line change to app code, so it waits for after the freeze. Low severity, recorded for triage.
- **Scope:** the middleware audits POST/PUT/DELETE on `/api/staff`, `/api/departments` and `/api/roles` only. Clinical-record changes are audited separately by the patient service's own record history (`…/records/{id}/versions`).
